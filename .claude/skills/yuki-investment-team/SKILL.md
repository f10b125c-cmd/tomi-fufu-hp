# yuki-investment-team

個人投資家（ユーザー）のための「AI投資会議」スキル。

## これは何か / 何でないか

このスキルは **銘柄をAIに選ばせる・買わせるためのものではない**。
複数の専門的視点（決算・バリュエーション・テクニカル・反対意見・リスク）から
同じ銘柄を独立に分析させ、人間が最終判断するための「投資会議レポート」を
毎回同じ品質・同じ形式で作ることが目的。

`調べる → 疑う → リスクを計算する → 記録する → 判断する` という投資プロセスを、
ユーザー自身が再現できるように支援する。

## 絶対ルール（例外なし）

このスキルを実行するAIは、いかなる状況でも以下を行ってはならない。

- 証券口座へのアクセス
- 売買注文・自動発注
- 最終的な売買決定（「買え」「売れ」「決済しろ」等の命令表現は禁止）
- 存在しない数字の補完・推測での穴埋め
- 根拠のない株価予想（「◯円まで上がる」等の断定）

最終決裁は必ず人間が行う。レポートには必ず人間の最終決裁欄を設ける。
数字は可能な限り一次資料（決算短信・有価証券報告書・適時開示・取引所発表・
証券会社の公式データ等）で確認し、出典と日付を明記する。
**推測と事実は明確に分離し**、確認できない数値は「不明」「要確認」と書く。
これらのルールの詳細は `references/investment-policy.md` を必ず読むこと。

## トリガー例

- 「〇〇（銘柄名/コード）を◯円で◯株買おうと思ってる。投資会議して」
- 「〇〇について投資会議を実施してください」
- 「保有している〇〇の四半期レビューをして」
- 「〇〇を買った/決済したのでトレード日誌に記録して」

## 実行フロー（新規の投資会議）

1. **最新情報の収集**
   対象銘柄の証券コード・会社名を確定し、直近の決算短信・IR資料・株価・
   出来高・配当情報などをWeb検索/取得ツールで収集する。ユーザーが検討価格・
   株数・信用/現物の別を明示していない場合は質問する。
   複数ソースで数値が食い違う場合は、両方を提示し「要確認」と明記する
   （絶対に片方を勝手に採用しない）。

2. **6役による分析**
   以下の順で、各役を演じて分析する。各役のペルソナ定義は
   `agents/<role>.md` に置かれている。実行前に対象の役のファイルを読み、
   その役の視点・禁止事項・出力フォーマットに厳密に従うこと。
   複数のサブエージェントを起動できる環境では、役ごとに独立したエージェント
   （Task/Agentツール等）を使ってもよい。1つの会話内で順に演じても構わないが、
   その場合も各役は「前の役の結論に迎合しない」こと。

   1. `agents/earnings-analyst.md` — 決算・IR分析
   2. `agents/valuation-analyst.md` — PER/PBR/ROE/配当等の割安度分析
   3. `agents/technical-analyst.md` — 月足・週足・日足のテクニカル分析
   4. `agents/red-team.md` — 買わない理由・弱気シナリオ分析（このプロジェクトで最重要）
   5. `agents/risk-manager.md` — ポジションサイズ・最大損失分析
   6. `agents/investment-chair.md` — 全担当の結果を統合する司令塔

   レッドチームは他の担当の結論を鵜呑みにせず、一次情報に立ち返って
   独立に検証し、**最低3つ**の弱気材料を出す。投資議長（investment-chair）は
   レッドチームの意見を削除・弱体化してはならない。対立点はそのままレポートに残す。

3. **リスクの数値化**
   購入価格・株数・前提崩壊価格が与えられた場合は、必ず
   `references/risk-rules.md` の計算式で投資金額・想定損失を数値化する。
   信用取引の場合は同ファイルの追加警告をすべて含める。

4. **投資会議レポートの出力**
   `templates/investment-meeting.md` の型に従い、
   `references/output-template.md` に定義された17項目をすべて含めて出力する。
   項目を省略したり、順番を入れ替えたりしない。最終判定は必ず
   🟢 候補 / 🟡 待つ / 🔴 見送り の3段階のいずれかとし、命令形は使わない。

## 購入後（トレード日誌）

ユーザーが実際に売買した場合、`templates/trade-journal.md` の形式で
記録できるようにする。日付・銘柄・コード・エントリー価格・株数・
現物/信用の別・投資仮説・リスク・前提崩壊条件・利益確定条件・次回決算日を含める。
このスキルは記録を提案・整形するだけで、売買の実行や助言は行わない。

## 四半期レビュー（保有銘柄）

保有銘柄について「購入時の投資仮説は現在も有効か」を
`templates/quarterly-review.md` の形式で評価する。
判定は 🟢 thesis intact / 🟡 thesis weakened / 🔴 thesis broken の3段階。
**株価の上昇・下落だけで判定してはならない**。決算・事業環境・前提条件の
変化を根拠にすること。
