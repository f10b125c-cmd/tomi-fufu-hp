|---|---|

# 1. 文書の目的
本書は、個人投資家が銘柄検討時に「決算・割安度・チャート・反対意見・リスク」を分業型AIで確認し、最終的に人間が意思決定できる「AI投資会議アプリ」のMVP要件を定義する。

> プロダクトの一文定義AIに銘柄を買わせるアプリではなく、AIに投資会議をさせて「判断漏れ」を減らすアプリ。

# 2. 背景・課題
- 個人投資家は、決算読解、バリュエーション、チャート、ポジションサイズ、反対意見、記録を一人で行うため、役割抜けが起きやすい。
- 一般的なAIへの「この銘柄どう思う？」という質問は、質問者のバイアスや聞き方に結果が左右されやすい。
- 特に「買わない理由」「前提崩壊条件」「最大損失」の確認が後回しになりやすい。
- 購入時の理由が記録されず、価格変動後に投資仮説ではなく感情で保有判断を変えやすい。
# 3. 目的・成功状態

| ID | 目的 | 成功状態 |
|---|---|---|
| G-01 | 分析の分業 | 1回の入力で6役の分析結果が揃う |
| G-02 | 反対意見の強制 | 必ず独立したレッドチームが最低3つの反対意見を出す |
| G-03 | リスクの数値化 | 投資金額・前提崩壊価格・想定損失を表示できる |
| G-04 | 判断の記録 | 購入時の仮説・リスク・前提崩壊条件を保存できる |
| G-05 | レビュー習慣 | 決算後/任意時点で「買った理由がまだ生きているか」を再評価できる |

# 4. 対象ユーザー
MVPの主対象は、日本株の個別株を売買する個人投資家。中長期・高配当・スイングを併用し、一部で信用取引も利用するユーザーを想定する。

| ペルソナ | 特徴 | 主なニーズ |
|---|---|---|
| P1 個人投資家 | 本業/家事の合間に投資。情報収集時間が限られる | 短時間で論点を網羅したい |
| P2 スイング併用 | 日足・週足・月足を使う | 今入る位置・支持線・前提崩壊を見たい |
| P3 中長期/配当 | 決算・還元・財務を重視 | 投資仮説を四半期ごとに見直したい |

# 5. MVPスコープ
## 5.1 MVPに含める
- 銘柄・検討価格・株数・現物/信用の入力
- 6役AIによる並列または段階分析
- 投資会議レポートの生成
- 買い材料 / 見送り材料 / 注目価格 / 前提崩壊条件の表示
- リスク金額の計算
- 投資判断の保存（トレード日誌）
- 保有/ウォッチ銘柄一覧
- 過去会議の履歴閲覧
- 決算後または任意タイミングでの投資仮説レビュー
## 5.2 MVPに含めない
- 証券口座へのログイン・API連携
- 自動売買・注文送信
- 「必ず上がる」などの収益保証
- AIによる最終的な売買決裁
- 超短期/HFT用途のリアルタイム秒足分析
- 税務申告機能
- SNS投稿やコミュニティ機能
# 6. AI組織要件

| 役割 | 責務 | 主な出力 | 禁止事項 |
|---|---|---|---|
| 決算担当 | 決算・業績・配当・CFの整理 | 良い点/悪い点/変化/次回確認点 | 数字の推測補完 |
| バリュエーション担当 | PER/PBR/ROE/配当・競合比較 | 割安/中立/割高＋根拠 | チャートだけで評価 |
| テクニカル担当 | 月足/週足/日足の位置判断 | 支持線/抵抗線/打診/追加/前提崩壊 | 企業価値を断定 |
| レッドチーム | 強気仮説を独立して否定検証 | 反対意見3件以上/最大懸念 | 他担当へ迎合 |
| リスク担当 | 投資金額・損失・集中・信用リスク | 最大想定損失/警告 | 買い推奨 |
| 司令塔 | 各担当を統合 | 3段階判定＋決裁書 | 反対意見の削除/弱体化 |

# 7. 機能要件

| ID | 機能 | 要件 | 優先度 |
|---|---|---|---|
| FR-001 | 新規投資会議 | 銘柄コード/企業名、検討価格、株数、現物/信用を入力し会議を開始できる | Must |
| FR-002 | 最新情報取得 | 分析時点の株価・IR・決算・公開情報を取得/参照できる | Must |
| FR-003 | 6役分析 | 6役を独立した指示で実行できる | Must |
| FR-004 | レッドチーム | 最低3つの反対意見を必須出力する | Must |
| FR-005 | 投資会議レポート | 結果を1画面の決裁書として統合する | Must |
| FR-006 | リスク計算 | 投資金額・想定損失を自動計算する | Must |
| FR-007 | 判断保存 | 会議結果・自分の最終判断・理由を保存できる | Must |
| FR-008 | 履歴 | 過去の会議を銘柄別/日付別に閲覧できる | Must |
| FR-009 | 仮説レビュー | 過去の購入理由と最新情報を比較し仮説の維持/弱化/崩壊を判定する | Should |
| FR-010 | 決算日管理 | 次回決算日を保存/表示する | Should |
| FR-011 | ウォッチリスト | 未購入銘柄を候補として保存できる | Should |
| FR-012 | PDF/共有 | レポートを出力・共有する | Could |

# 8. 投資会議レポート要件
- 総合判定は「候補 / 待つ / 見送り」の3段階とし、「買え」「売れ」などの命令表現は使わない。
- 決算・割安度・チャート・レッドチーム・リスクの各セクションを固定順で表示する。
- 買い材料3件、見送り材料3件を明示する。
- 打診候補価格、追加候補価格、上抜け確認価格、前提崩壊価格または条件を表示する。
- 数字には出典または取得元を紐づけ、未確認の数字は「未確認」と表示する。
- 最後に「人間が確認すべき項目」と「最終決裁：人間」を表示する。
# 9. 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | 通常の投資会議はユーザーが結果待ち可能な範囲で完了し、各担当の進捗を表示する。 |
| 可用性 | 外部データ取得が失敗しても、取得できた範囲と不足情報を明示して部分結果を返す。 |
| セキュリティ | MVPでは証券口座認証情報を保存しない。認証情報・APIキーはサーバ側秘密情報として管理する。 |
| プライバシー | ユーザーの投資履歴・資産情報はユーザーごとに分離し、公開しない。 |
| 監査性 | AI出力、入力、使用データ、生成日時を会議単位で保存できる。 |
| 説明可能性 | 判定だけでなく根拠を必須表示する。 |
| モバイル | スマートフォン縦画面を最優先し、主要操作は1〜2画面で完結する。 |
| 拡張性 | AIモデル、データソース、分析役を後から追加・差し替えできる。 |

# 10. UX要件

| 画面 | ユーザーの主行動 | 要点 |
|---|---|---|
| ホーム | 会議開始 / 保有・候補確認 | 「新しい投資会議」を最上部に配置 |
| 会議入力 | 銘柄・価格・株数・取引種別入力 | 入力項目を最小化。任意で投資理由メモ |
| 会議進行 | 6役の進捗確認 | 「決算分析中」「レッドチーム検証中」など可視化 |
| 会議結果 | 決裁書を読む | 総合判定→反対意見→リスクを上部に寄せる |
| 保存 | 自分の最終判断を記録 | 購入/見送り/保留と一言理由 |
| 銘柄詳細 | 履歴と仮説を確認 | 過去会議→最新レビューへ遷移 |

> UX上の重要方針「強気材料」よりも先に、レッドチームと最大想定損失を見つけやすくする。ユーザーを買い方向へ誘導しない。

# 12. 安全・ガードレール要件
- 最終決裁は常に人間であることをUIとデータモデルの両方で表現する。
- AIが証券口座へ接続・注文しない。
- 数字の原本確認を促し、出典のない数字を確定値として扱わない。
- 未来の株価・リターンを断定しない。
- 信用取引は現物より厳しいリスク警告を表示する。
- レッドチームの反対意見を司令塔が削除しない。
- ユーザー入力が不足している場合は、推測で埋めず「不足」として扱う。
# 13. MVP受入基準

| AC | 受入条件 |
|---|---|
| AC-01 | 銘柄・価格・株数・現物/信用を入力して投資会議を開始できる |
| AC-02 | 6役すべての結果が保存される |
| AC-03 | レッドチームが独立して最低3件の反対意見を生成する |
| AC-04 | 投資金額と最大想定損失が計算される |
| AC-05 | 結果画面に候補/待つ/見送りの総合判定が表示される |
| AC-06 | ユーザーが最終判断を保存できる |
| AC-07 | 過去の判断と理由を後から参照できる |
| AC-08 | AIが売買発注を行う経路が存在しない |
| AC-09 | 取得失敗や未確認情報が明示される |
| AC-10 | スマホ縦画面で主要フローが完結する |

# 14. KPI（MVP検証）
- 会議完了率
- 会議1件あたりの閲覧完了率
- レッドチーム開封/閲覧率
- 判断保存率
- 同一銘柄の再レビュー率
- 「自分では気づかなかった論点があった」自己評価
- AIが当たったかではなく、判断プロセスが改善したかを主要評価とする。
# 15. 将来拡張
- 株主還元担当、競合比較担当、マクロ担当、需給担当、適時開示担当、決算カレンダー担当の追加
- 保有ポートフォリオ全体のセクター集中・ドローダウン管理
- 定期レビュー通知
- レポート共有/PDF化
- 法人向けチーム利用
- データプロバイダ連携（規約・ライセンス確認前提）
# 16. 未決事項

| 論点 | MVP方針 |
|---|---|
| 株価データ供給元 | 開発時に利用規約・更新頻度・コストを比較し確定 |
| IR/適時開示取得 | 公式/一次情報優先。取得方式は実装時に確定 |
| 認証 | 個人利用なら簡易認証でも可。公開時は標準認証へ |
| 課金 | MVPでは対象外。SaaS化時に会議回数/分析深度で設計 |
| モデル選定 | 特定モデル固定ではなく、役割ごとに差し替え可能な抽象化を採用 |
