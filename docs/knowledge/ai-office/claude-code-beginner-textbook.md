## Lecture 1: Claude Codeとは何か

Claude Codeは「あなたの仕事用フォルダへ入り、必要な資料を読みながら、実際の作業まで進めるClaude」。通常のチャットAIとの違いは、**仕事の中心が会話かプロジェクトフォルダか**という点にある。

- 通常のチャットAI: 会話中心。資料を添付→回答をチャットで受け取る→結果は自分で保存
- Claude Code: フォルダ・ファイル中心。資料を自分で探す→ファイルの作成・編集まで行う→複数工程の仕事を継続して進める→プロジェクト専用のルール・手順を保存できる

「Code」という名前だが、対象はプログラミングに限らない。ライター・編集者、マーケター、営業、経営者・事業責任者、バックオフィスなど、**パソコン上のファイルを使う知的作業全般**に適用できる（記事構成・競合LP比較・商談記録整理・週報作成・社内文書分類など）。

## Lecture 2: 15分セットアップ

Claude Codeはターミナルだけでなく、Desktop、VS Code、JetBrains、ブラウザからも利用可能。「黒い画面が怖い」場合はDesktop/VS Codeからでもよいが、基本を理解するにはターミナル版を一度触るとよい。

### インストール（確認済み・正確）

```bash
# Mac / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# Windows（WinGet）
winget install Anthropic.ClaudeCode
```

インストール後に`claude`コマンドが見つからない場合はターミナルを開き直す。

### 練習用フォルダを作る

```text
claude-practice/
├── company-profile.md
├── meeting-note-01.txt
├── meeting-note-02.txt
├── competitor-a.md
└── competitor-b.md
```

最初は大切な仕事のフォルダではなく、読ませても問題ない資料を3〜5個入れた練習フォルダで試す。

### 起動とPlan Mode

```bash
claude
```

初回はブラウザでログインが求められる。`ANTHROPIC_API_KEY`が設定されているとサブスクリプションでなくAPI課金が使われる場合があるため、意図しない課金を避けたい場合はログイン方法と`/status`の表示を確認する。

**Plan Mode**（ファイルを読んで計画を提案するだけで、勝手に編集しないモード）は、非エンジニアが安全に始めるための重要な機能。

- **主な入り方（公式が案内する方法）**: 対話中に**Shift+Tabキー**で権限モードを循環切り替え（default → acceptEdits → plan → auto）
- 起動時に指定: `claude --permission-mode plan`
- 依頼の前に`/plan`を付ける: `/plan このフォルダの資料を分析し、競合比較レポートを作る手順を提案してください。`

### 最初に覚える5つの操作（確認済み）

| コマンド | 内容 |
|---|---|
| `claude` | 起動 |
| `/exit`（`/quit`も可） | 終了 |
| `/status` | 利用状況の確認 |
| `/mcp` | 接続中のMCPサーバーを確認 |
| `/permissions`（`/allowed-tools`も可） | 権限ルールの確認 |

## Lecture 3: 最初の仕事を安全に任せる

最初に体験すべきは「Claudeがフォルダを読み、複数資料をまとめ、成果物を保存する」流れ。いきなりアプリを作らせる必要はない。

### 練習プロンプト（読み取りのみ）

```text
このフォルダ内にある資料をすべて確認してください。
最初はファイルを変更せず、
次の内容だけ報告してください。

1. 各ファイルの概要
2. 資料間で共通している内容
3. 情報が食い違っている部分
4. 不足している情報
5. 作成できそうな成果物
```

### 成果物作成の練習

```text
先ほどの分析をもとに、
outputs/summary.mdを作成してください。

内容は次の構成にしてください。
1. 全体の要約
2. 重要な発見
3. 資料間の共通点
4. 矛盾している点
5. 次に確認すべきこと

元ファイルは変更しないでください。
情報がない部分は推測しないでください。
```

### 依頼は5項目で組み立てる

```text
## 目的
[何のために行うのか]

## 入力
[どのファイル・フォルダを使うのか]

## 作業内容
[何を行うのか]

## 完了条件
[何ができたら終了なのか]

## 制約
[変更禁止、確認が必要な操作、推測禁止など]
```

**「説明」より「完了条件」が重要。** 「競合を詳しく調べてください」ではなく、「価格・対象顧客・主要機能・強み・弱みを整理し、比較表をMarkdownで保存、経営会議用HTMLも作成、情報がない項目は『未確認』と記載、根拠URLを付ける」まで具体化する。

## Lecture 4: CLAUDE.mdと記憶の仕組み

CLAUDE.mdは「Claudeの永続記憶」ではなく、**Claude Codeが各セッションで読む、プロジェクトの継続的な指示書**。セッションをまたぐ知識の引き継ぎには、人間が書くCLAUDE.md（明示的な指示・ルール）と、Claudeが作業中に学んだ内容を保存する自動メモリの2種類がある。どちらも強制的な設定ではなく、絶対に止めたい操作は権限設定やHooksで制御する。

### 書くべきもの／書かなくてよいもの

| 書くべき | 書かなくてよい |
|---|---|
| プロジェクトの目的、読者・顧客、毎回守る重要ルール、成果物の保存場所、既存ファイルの役割、安全ルール | 一度しか使わない依頼、ファイルを見れば分かる内容、長い作業手順、過去の会話まとめ、起きるか分からない失敗への大量の禁止事項 |

**公式ガイドライン（確認済み）**: CLAUDE.mdは1ファイル**200行以下**を目安にする。長すぎるファイルはコンテキストを圧迫し、指示への追従性を下げる。初心者はまず10〜30行で十分。

### 初心者向けCLAUDE.mdテンプレート

```markdown
# Project
このフォルダは、
AIに関する記事とX投稿を制作・管理するプロジェクトです。

# Audience
主な読者は、
AIを仕事へ活用したい日本人のビジネス層です。
専門用語は、初心者でも理解できるように説明してください。

# Writing
- 結論から書く
- 抽象論だけで終わらず、具体例を入れる
- 不自然なAI表現を避ける
- 同じ内容を繰り返さない
- 自然な日本語で書く
- 事実と推測を区別する

# Output
- 記事は outputs/articles/ に保存する
- X投稿は outputs/x-posts/ に保存する
- 比較資料はMarkdownとHTMLの両方を作る
- 最新情報を使った場合は参照元を残す

# File Rules
- references/ の元資料は変更しない
- 既存ファイルを削除しない
- ファイル名は英数字とハイフンを使用する

# Safety
- 外部公開、メール送信、課金、削除は実行前に確認する
- APIキー、個人情報、機密情報を出力しない
```

### 追記のタイミング

同じ間違いが2回起きた／同じ説明を何度も入力している／チームメンバーも知る必要がある／プロジェクト固有の重要事項がある、のいずれかが起きたら追記を検討する。一度しか起きていない問題を即ルール化すると肥大化する。

`/init`（確認済み）を実行すると、Claudeがプロジェクトを分析しCLAUDE.mdの作成・改善案を支援する。ただし自動生成をそのまま使わず、「本当に毎回必要か」「ファイルを見れば分かる内容ではないか」「古い情報が混ざっていないか」「長すぎないか」を確認する。

## Lecture 5: Claude Codeを強くする4つの仕組み

| 仕組み | 身近な例え | 役割 |
|---|---|---|
| Skills | 作業マニュアル | 何度も使う知識・手順・チェックリストを保存 |
| Subagents | 専門担当者 | 別コンテキストで仕事を進め、結果の要約を返す |
| MCP | 外部サービスへの接続口 | 外部ツール・DB・APIとの接続 |
| Hooks | 自動で作動する安全装置 | 特定のタイミングで確実に実行される自動処理 |

### Skills（訂正あり）

プロジェクト専用Skillsは `.claude/skills/` に置く（**確認済み・正しい**）。

```text
.claude/
└── skills/
    └── write-article/
        ├── SKILL.md
        ├── style-guide.md
        └── approved-examples.md
```

**⚠️ 訂正**: Skill名は**ディレクトリ名から自動的に決まる**。`SKILL.md`のフロントマターに`name`フィールドを書く必要はなく、書いても反映されない。フロントマターに必須なのは`description`（Claudeがこのスキルをいつ自動読み込みするか判断する材料になる）。以下のテンプレート例は`name`行を削除して使うこと。

```markdown
---
description: AIや業務効率化に関する長文記事を企画・調査・執筆するときに使用する
---

# Article Workflow

## 1. 目的を整理する
- 誰が読むのか
- 読者が抱えている問題
- 最も伝えたい結論
- 読後に取ってほしい行動

## 2. 情報を確認する
- ユーザーから渡された資料を優先する
- 現在性のある情報は一次情報を確認する
- 事実と推測を区別する
- 根拠のない数値を作らない

## 3. 構成を作る
- 冒頭で読者の悩みを具体化する
- 早い段階で結論を示す
- 抽象論の後に具体例を入れる

## 4. 執筆する
- 自然な日本語で書く
- 同じ内容を繰り返さない
- 他社記事の表現や構成をコピーしない

## 5. 最終確認する
- 誤字脱字、重複表現、不自然な断定、出典のない数値、実践性
```

CLAUDE.mdとSkillの違い: **常識はCLAUDE.md、手順はSkill**。同じ説明を3回以上しているならSkill化を検討する。

### Subagents（確認済み）

メインのClaudeとは別のコンテキストで仕事を進め、結果の要約を返す。複数企業の独立調査、大量ファイルからの情報探索、セキュリティ/品質/事実確認を別視点で行う、といった用途に向く。

一方、前工程の結果が必要／一つの短いファイルだけを扱う／同じデータを同時編集する／数回の処理で終わる、といった仕事は一つのClaudeが順番に進める方が安定する。Subagentsも利用量・APIコストを消費するため、最初は1体で進め、明確に独立した仕事だけを分ける。

### MCP（確認済み）

Model Context Protocolの略。Claude Codeと外部のツール・DB・APIをつなぐ接続口。サービスごとにMCPサーバーの有無・対応機能・認証方法・読み書き権限・対応プランが異なる。

**最初は読み取り専用から始める**のが安全（[MCPツール自動化事例集](./mcp-tools-automation-50.md)の安全装置6項目とも一致）。読み取り→下書き作成→限定された書き込み→人間の承認後に実行、の順で権限を広げる。接続状況は`/mcp`で確認できる。

### Hooks（確認済み）

CLAUDE.mdへの指示は「Claudeへの指示」であり物理的なブロックではない。**絶対に止めたい処理にはHooksを使う**——特定のタイミングで確実に自動実行される仕組み。ファイル編集後の自動チェック、危険なコマンドの実行前ブロック、完了時通知、外部送信前の確認などに使う。

> Claudeへ判断してほしいことは指示に書く。必ず守らせたいことは権限とHooksで制御する。

## Lecture 6: 職種別・実践ワークフロー

共通の基本形: 資料を置く → Claudeに読ませる → 分析・作成させる → 成果物をファイルへ保存する → 人間が確認する → 繰り返す仕事はSkill化する。

- **記事制作**: `references/`に一次情報・競合記事を置き、「他社記事をコピーしない」「一次情報優先」「専門用語は最初に説明」を条件に`drafts/article.md`へ下書き保存させ、完成前に構成と不足情報を先に報告させる。
- **会議・インタビュー分析**: `transcripts/`の複数記録から共通課題を5つ以内に分類し、該当発言・発言者数を付け、少数意見も別枠で残し、`outputs/insights.md`へ保存。
- **競合調査**: 独立性が高いためSubagentsを活用可能。対象顧客/価格/主要機能/強み/弱み/最近の発表/自社への影響を、根拠URL・取得日付きで整理し、Markdown＋HTMLの両方を出力。
- **週報の自動作成**: `project-notes/`・`meeting-notes/`・`tasks.csv`・`git log`から、結論／完了事項／遅延事項／KPI／要判断事項／来週の優先順位、の構成でMarkdown＋HTMLを生成。元データは変更しない。
- **簡単な業務ツール作成**: プログラミング未経験でも1機能に絞れば着手可能（例: CSV読み込み＋カテゴリ絞り込み＋検索のHTMLツール）。外部サーバーへ送信しない、単一HTMLファイルにまとめる、外部ライブラリ不使用、といった制約を明示し、**まずPlan Modeで設計だけ提示させる**。顧客データ・個人情報・決済・本番環境が絡む場合は人間レビュー必須。

## Lecture 7: 4週間で仕事へ定着させる

| 週 | 目標 |
|---|---|
| Week 1 | 基本動作に慣れる（インストール→練習フォルダ→Plan Modeでの説明→複数資料の要約→1ファイル保存→20行程度のCLAUDE.md作成）。外部サービス接続は不要 |
| Week 2 | 実際の仕事を一つ任せる（毎週/毎月行っている・ファイルを読み整理する・失敗しても大きな問題にならない・人間が確認できる仕事。週報/議事録/記事構成/競合調査/アンケート分類が候補）。下書き作成までの半自動で十分 |
| Week 3 | Week 2で繰り返した仕事をSkill化する（同じ説明を3回したら検討、最初から大量に作らない） |
| Week 4 | 必要な拡張だけ追加する（毎回別サービスから同じ情報をコピーしているならMCP、独立した調査を同時進行したいならSubagent、必ず実行/絶対阻止したい操作があるならHook） |

機能を増やすこと自体は目的ではない。**自分の仕事から不要なコピペと説明の往復を一つずつ消すこと**が目的。

## 初心者が避けるべき10の失敗

1. 最初から完全自動化する → まず下書き作成までにし、人間が確認する
2. 大切なフォルダで練習する → コピーした資料か練習用フォルダを使う
3. 最初から自動編集させる → Plan Modeや確認付き権限から始める
4. CLAUDE.mdへ何でも書く → 毎回必要な情報だけ残す
5. Skillsを大量導入する → 実際に使うものだけに絞る
6. Subagentsを増やしすぎる → 独立していない仕事は一つのClaudeへ任せる
7. MCPへ広い権限を渡す → 最初は読み取り専用にする
8. APIキーをファイルへ直接書く → 環境変数や安全な認証方法を使う
9. 外部情報を無条件に信用する → MCPやWebから取得した情報には誤情報や悪意ある指示が含まれうる
10. 出力を確認せず使う → 事実・数字・送信内容・公開物は人間が確認する

## 料金と利用量（確認済み・2026年8月時点）

- **Pro**: 月額20ドル
- **Max 5x**: 月額100ドル
- **Max 20x**: 月額200ドル

Pro・Maxの利用量はClaudeのWeb/Desktop/モバイル/Claude Codeで共有されるとの記載があるが、この使用量プーリングの詳細仕様は公式ドキュメントで直接確認できなかった（claude-code-guideの調査でも未確認）。APIを利用する場合はサブスクリプションと別に従量課金が発生する。**料金・上限は変更されるため、契約前に[Anthropic公式サイト](https://www.anthropic.com/pricing)で最新情報を確認すること。**

利用量が増えやすい使い方: 大量ファイルの毎回読み直し、長い成果物の何度も再生成、Subagentsの多数起動、同じ処理の繰り返し、不要なMCP出力の大量取得、対象範囲を決めないフォルダ全体分析。節約策: 対象ファイルの指定、完了条件の明確化、出力形式・長さの指定、繰り返し手順のSkill化、`/status`での利用状況確認。

## AIオフィスへの適用メモ

- このガイドは、既存の[AI社員7人体制](./ai-shain-7nin-claude-code.md)（フォルダ構成・CLAUDE.md設計・失敗パターン）や[MCPツール自動化事例集](./mcp-tools-automation-50.md)（MCP安全設計）と非常に整合性が高く、**Claude Code導入の公式寄りリファレンス**として他のナレッジより優先度高く参照できる。
- 「常識はCLAUDE.md、手順はSkill」という切り分けは、AI社員7人体制の`agents/`（役割定義）と`knowledge/`（前提知識）の使い分けにも直接対応する。

- 4週間ロードマップ（Week1:慣れる→Week2:1つ任せる→Week3:Skill化→Week4:拡張）は、新規にAIオフィスを立ち上げる際の導入計画のテンプレートとして流用できる。
