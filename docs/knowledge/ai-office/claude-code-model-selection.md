## 3モデルの基本的な使い分け

| モデル | 得意な仕事 | 特徴 |
|---|---|---|
| **Sonnet** | 日常的な実装・作業全般 | 速度と品質のバランスが良く、通常作業の中心に据えるのが基本方針 |
| **Opus** | 設計方針の決定／原因の深い分析／大量情報の読み解きなど「考える仕事」 | 高度な推論で優位。Sonnetを前線に立たせ、Opusは判断・レビュー役に絞る運用が推奨 |
| **Haiku** | 大量ファイルの分類・整理、簡単な質問への回答、下調べなど「スピード重視の大量作業」 | 処理速度が速く、コストも低い。最終判断はOpus/Sonnetに委ねる「部下」的役割 |

### ベンチマークによる裏付け（検証済み）

- **SWE-bench Verified（実務的なソフトウェアエンジニアリングタスク）**: Opus 80.8% / Sonnet 79.6% → 差は1.2%。日常的な実装作業では体感差が小さいという主張の根拠になる。
- **GPQA Diamond（大学院レベルの高度な推論）**: Opus 91.3% / Sonnet 74.1% → 差は17.2%。高度な推論が必要な場面ではOpusの優位性がはっきり出る。

→ **「日常作業はSonnet、高度な設計・推論はOpus」という使い分けの方向性自体は、公開ベンチマークと整合する。**

## Opusを常用すると起きる問題

Opusを最前線の作業に常時使うと、利用枠（レート制限）の上限に達しやすくなる。「さっきまで動いていたのに急に止まった」「月の半ばなのに残り枠がゼロになった」といった状態は、モデル選択のミスマッチが原因になりやすい。Sonnetをメインにするだけでも改善するとされる。

## `opusplan`モード（検証済み・実在する機能）

Claude Codeの公式モデルエイリアスとして実在する機能。

- **仕組み**: プランモード（設計・方針決定フェーズ）では**Opus**を使い、実行フェーズになると自動的に**Sonnet**へ切り替わる。
- **設定方法**:
  ```text
  /model opusplan
  ```
- 手動でモデルを切り替える手間をなくし、Opusの思考力とSonnetのコスト効率を両立させるモード。

（[Claude Code公式ドキュメント: Model configuration](https://code.claude.com/docs/en/model-config.md)）

## `/effort`コマンド（検証済み・実在するがモデル依存）

モデルを切り替える前に、まず「思考の深さ」を調整するというアプローチ自体は理にかなっている。

```text
/effort medium
```

- レベル: `low` / `medium` / `high` / `xhigh` / `max`（**対応レベルはモデルにより異なる**。Opus 4.6・Sonnet 4.6は`xhigh`非対応）
- 基本方針: 普段の作業は`medium`、重要な分析は`high`、最難関の判断のみ`xhigh`/`max`に留める。全てを`max`にすると利用枠の消費が急増するため非推奨。

## モデル切り替えコマンド（検証済み）

```text
/model sonnet
/model opus
/model haiku
/model opusplan
```

いずれも公式のClaude Code機能で、各モデルファミリーの最新版に解決される。

## 実践的な3ステップ運用（元記事の提案・妥当性は高い）

1. **Sonnetで始める**: `/model sonnet` を基本とする
2. **物足りなければ深さを上げる**: モデルを変える前に `/effort high` を試す
3. **それでも足りなければOpusへ**: 設計判断や複雑な分析が必要な場面のみ `/model opusplan` に切り替え、作業終了後はSonnetに戻す
