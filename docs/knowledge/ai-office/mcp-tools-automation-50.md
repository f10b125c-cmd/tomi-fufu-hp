# MCPツール自動化事例集（50ツール＋実践ワークフロー）

- **出典**: [mana｜株式会社MakeAI CEO (@MakeAI_CEO) のポスト](https://x.com/MakeAI_CEO/status/2091169088622195169)（2026年8月22日）
- **対象**: 日本人が使いやすい主要MCP（Model Context Protocol）ツール50種と、複数MCPを連携させた実践的な自動化ワークフロー
- **用途**: AIオフィスでの業務自動化構築時のツール選定・安全設計のリファレンス

## MCPの本質と誤解の整理

- MCP（Model Context Protocol）は、AIアプリと外部のデータ・ツール・業務フローを接続するオープンな標準規格。「AI向けのUSB-C」と例えられるが、本質は**AIが必要なツールを自分で選び、複数サービスをまたいで仕事を進められること**（[Model Context Protocol公式](https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro)）。
- **誤解注意**: MCPを入れただけでは自動で動き出さない。MCPは「AIに道具を渡す仕組み」であり、時刻やイベントを検知する仕組みではない。

### 本当の自動化に必要な構成

```text
新着メール・時刻・フォーム回答・Webhook・新規レコード
        ↓
Zapier・Make・n8n・Pipedream（トリガー）
        ↓
AIエージェントが内容を判断
        ↓
MCP経由で必要なツールを選択・実行
        ↓
人間の承認・実行・ログ保存
```

役割分担: **トリガーはワークフロー系ツール、判断はAI、実行はMCP**。

2026年8月22日時点では公式MCP Registryが整備され、正体不明のGitHub実装を探し回らなくても公式・準公式実装を見つけやすくなっている（[MCP Registry](https://registry.modelcontextprotocol.io/)）。ただし公式リファレンスサーバーも教育・検証用であり、そのまま本番利用は非推奨。「公式=安全」ではなく、**権限・ログ・承認フローの設計が必須**。

### MCPの4分類

| 分類 | 内容 |
|---|---|
| 公式MCP | サービス提供企業が公開しているMCP |
| ワークフローMCP | Zapier/Make/n8nなどで処理を1つのMCPツールとして公開 |
| API→MCP | 公式APIをn8nやPipedreamなどから呼び出す |
| コミュニティMCP | 第三者実装。原則として読み取り専用から始める |

## 複数MCPを連携させた実践自動化事例

1. **請求書処理の自動化**: Gmail検出→Drive保存→AI抽出（会社名/日付/金額/税区分）→重複確認→freee下書き→Slack承認→処理済みラベル。**最後の会計判断だけ人間に残す**。
2. **リサーチ→SNS投稿の自動化**: GA4/Search Consoleで伸長/低迷テーマ検出→Exa/Firecrawlで追加調査→Notionで構成→記事完成→Canva画像→Runway/HeyGen動画→ElevenLabs音声→YouTube非公開アップロード→X/Instagram/LINE投稿案→人間承認・公開。**AIにゼロからネタを考えさせず、実データから着想する**のが薄いAIコンテンツ化を防ぐ鍵。
3. **商談準備〜営業フォローの自動化**: Calendly予約→Calendar登録→Exa企業調査→Gmail過去やり取り取得→HubSpot/Salesforce顧客情報→Notion準備ページ→Slack通知→Zoom商談→議事録要約→CRM更新案・フォローメール作成→人間承認。
4. **会議→タスク変換の自動化**: Zoom文字起こし→決定事項/保留/タスク抽出→Notion/Confluence議事録→Jira/Asana/ClickUp/Linearへタスク案→Slack確認→承認後登録→Calendar期限登録。**「要約するだけ」で終わらせず、担当者と期限付きタスクまで変換することに価値がある**。
5. **EC売上改善の自動化**: Shopify売上/在庫/返品→Stripe決済状況→AI問題商品抽出→HubSpotセグメント→Canva販促画像→LINE/Instagram/メール配信案→承認・配信→GA4計測。
6. **APIのない業務システムの自動化**: n8nスケジュール起動→Playwright管理画面操作→レポートDL→Sheets保存→AI異常値分析→Slack報告。**振込・返金・契約・削除・公開設定変更など取り返しのつかない操作は自動化対象外**、読み取り・ダウンロードに限定する。

## 失敗しないMCPワークフローの作り方

MCP自動化が失敗する最大の理由は**AIの性能ではなく、業務の完了条件が曖昧なこと**。以下のテンプレートで業務を定義する。

```text
【目的】 顧客から届いた問い合わせに対する返信準備を完了する。
【トリガー】 Gmailに「問い合わせ」ラベルが付いた時。
【入力】 メール本文、送信者、過去のメール、顧客情報、FAQ。
【使用してよいツール】 Gmail検索、Drive検索、Notion検索、Gmail下書き作成。
【禁止】 自動送信、メール削除、顧客情報の変更。
【処理】
1. 問い合わせ内容を分類する。
2. 必要な情報を検索する。
3. 回答案を作る。
4. 根拠資料を付ける。
5. Gmailに下書きを作る。
6. Slackへ確認依頼を送る。
【確認が必要な条件】 返金、契約、法務、クレーム、個人情報を含む場合。
【完了条件】 Gmailに返信下書きがあり、Slackに確認依頼が投稿されている。
【ログ】 実行日時、参照資料、判断内容、作成した下書きURLを保存する。
```

この形にすると「AIが何となく動く自動化」から「完了条件を満たす業務システム」に変わる。

## MCP自動化で必ず入れるべき安全装置（6項目）

1. **最初は読み取り専用にする**: 作成・更新・削除・送信は最初から許可せず、検索・取得・要約だけで1〜2週間動かして判断精度を確認する。
2. **下書きと本実行を分ける**: メール送信・SNS投稿・顧客情報更新・価格変更・公開・削除・返金・契約・一斉配信は原則承認を挟む。「AIが作る」と「AIが実行する」は別権限。
3. **専用アカウントを使う**: 管理者アカウントをそのままAIへ渡さず、必要なフォルダ/チャンネル/プロジェクト/アプリのみアクセス可能なAI専用アカウントを作る。
4. **細かいツールを大量に渡さない**: 低レベル操作を大量公開すると誤順序実行のリスクが上がる。Make/n8nで業務処理をまとめ、`create_sales_followup`のような大きな単位で公開する。
5. **すべての実行を記録する**: 実行日時・トリガー・入力データ・AIの判断・呼び出したツール・作成/変更対象・エラー・承認者・最終結果を最低限保存する。
6. **コミュニティMCPを無条件で入れない**: 開発元・更新状況・ソースコード・要求権限・保存データ・外部通信先を確認する。公式リファレンス実装であっても「本番運用向けではなく教育目的」と明記されているものがある。

## 最初に何を入れるべきか（推奨スターターセット）

50個を一気に導入する必要はない。ほとんどの場合、以下の10個で十分。

> Gmail / Google Drive / Google Calendar / Google Sheets / Notion / Slack / Canva / Make または Zapier / n8n / Firecrawl または Exa

この10個で、メール処理・ファイル整理・日程調整・データ管理・ナレッジ管理・社内通知・画像作成・Webリサーチ・定期実行・人間承認までを組める。用途別の追加候補:

- 動画制作: Runway / HeyGen / ElevenLabs
- 開発: GitHub / Figma / Linear / Playwright
- 営業強化: Calendly / HubSpot または Salesforce
- 日本企業バックオフィス: freee / kintone / LINE公式アカウント

## まとめ

MCPの価値は接続数を増やすことではなく、**毎日繰り返している仕事をAIが最後まで終わらせられる状態を作ること**。メールを要約するだけでは自動化と言えない。要約結果から資料を探し、返信を作り、タスクを登録し、担当者へ確認を出し、承認後に実行し、ログを残す——そこまでつながって初めて、MCPは「便利なAI機能」から「仕事を動かす業務基盤」になる。

## AIオフィスへの適用メモ

- [AI社員7人体制](./ai-shain-7nin-claude-code.md)の役割定義（agents/配下の定義書）に、各役割が使ってよいMCPツールと禁止操作を明記する形で組み込むと、権限設計がより具体化する（例: 経理担当にはfreee MCPを読み取り+下書き作成のみ許可し、確定登録は人間承認とする）。
- 「安全装置6項目」は、既存ナレッジの「フォールバック設計」「複数AI相互監査」と合わせて、AIオフィス全体の運用ガードレールのベースにできる。
- スターターセット（10ツール）は、新規にAIオフィスを立ち上げる際の最小構成の参考にする。
