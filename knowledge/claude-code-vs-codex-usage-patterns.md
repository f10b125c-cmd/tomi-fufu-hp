# Claude CodeとCodexの使い分け事例と、ルールファイルの一本化

> 「AIオフィス」＝Claude CodeとCodexの中に、AIの社員が働く環境を作るという著者の構成。最初の依頼（AIオフィス用のナレッジ化）と、これまでの「Codexに第二意見を聞く」流れは、この記事の考え方と同じ方向にある。

## 背景（記事の主張）
- 2026-09-22、AnthropicがClaude Opus 5.5を、OpenAIが「GPT-6 Sol」「GPT-6 Luna」を同日発表。Opus 5.5はClaude Code、GPT-6 Sol/LunaはCodexで使える。
- どちらも「上位モデルの強みを、より速く、より安く」を打ち出している。
  - Opus 5.5：多くの仕事でFable 5.1並みの性能、費用はOpus 5より約4割安、回答は3割以上速い（Anthropic発表とされる）。
  - GPT-6 Sol：最上位「GPT-6 Astra」の強みをより速く安く使えるモデル（OpenAI発表とされる）。

## 使い分けの事例（日英50本近くを調査した結果の抜粋）
結論は「人によってかなり違う」。共通するのは**どの作業をどっちに任せるかを先に決めている**こと。

| # | 分担 | 補足 |
|---|---|---|
| ① | Claude Codeが実装・動作確認 → Codexが変更箇所をレビュー（不具合・情報漏れにつながる危ない書き方） | Codexの指摘はClaude Codeに日本語で要約させ、**どれを直すかは人が決める** |
| ② | 両方が同じアプリを別々にレビュー | Codexだけが見つけた指摘は、Claude Codeに「本当に問題か」を確認させる。実例：Claude Codeが見落とした情報漏れリスクをCodexが発見 |
| ③ | Claude Codeが設計（どこをどう書き換えるか）→ Codexが実装し、動くまで自分で直す | Claude Codeの月額枠が足りなくなり、手間のかかる作業をCodexに回したのがきっかけ |
| ④ | 普段はClaude Code、困ったときだけCodexに相談 | 2回直しても直らない不具合の原因や、後から変えにくい重要な決めごとに意見をもらう。**Codexには書き換えさせず意見だけ** |

方向性は大きく2つ：
- **Claude Codeが作り、Codexが見直す（①②④）**：日本語圏で最も多い。理由の裏付けとして「同じAIに自分の答えを見直させると正解率がかえって下がることがある」という研究が引かれている（Google DeepMind等の論文、arXiv 2310.01798。自分の間違いは自分では見つけにくい）。
- **Claude Codeが設計し、Codexが作る（③）**：英語圏で特によく見る。

## 著者の使い方（AIオフィス）
- Claude Codeが作ったものをCodexに見直してもらう（例：8月に会社のルール文書を見直し、直すべき点13件・的外れな指摘0件）。
- 逆パターンもある：ゲームの3DキャラはCodexがメインで作り、Claude Codeが見直す。
- 手持ちの情報で書く記事 → Claude Codeで最後まで書く（過去の記録がそのまま材料になるため）。
- 調べ直しが必要なとき → Claude Code/Codexではなく、ClaudeやChatGPTのAIチャットでリサーチしてから情報をまとめる。

## ルールファイルは1つにまとめられる
- Claude Codeは `CLAUDE.md`、Codexは `AGENTS.md` を読む。同じルールを2か所に書くと片方だけ直し忘れる（著者は8月時点でCodex側だけ1か月以上古かった）。
- **Claude Code 2.1.277**以降、`CLAUDE.md`が無いフォルダでは代わりに`AGENTS.md`を読む。→ ルールを`AGENTS.md`に一本化すれば両方のAIが同じルールで動く。
- **注意**：作業フォルダ（とその上の階層）に`CLAUDE.md`が残っていると`AGENTS.md`は読まれない（[公式ドキュメント](https://code.claude.com/docs/en/memory#agents-md)）。
- 一本化の方法は2つ：
  1. `CLAUDE.md`を消して`AGENTS.md`だけにする
  2. `CLAUDE.md`に **`@AGENTS.md` と1行だけ書く**（著者はこちら）
- 「AGENTS.mdを読んでね」と文章で書くだけでは、AIが開こうとしたときにしか読まれない。**`@`を付けて書く**のがポイント（その場で中身が読み込まれる）。

## 検証メモ（鵜呑みにしない点）
- **「Opus 5より4割安い」**：公式単価は Opus 5.5 が $4/$20、Opus 5 が $5/$25（claude-apiスキルの2026-09-25キャッシュ値）で、**トークン単価では20%減**。4割は「1タスクあたりの費用（使うトークンが減る分を含む）」の話と思われるが、この記事だけでは確認できない。
- GPT-6 Sol/Luna/Astraに関する記述はOpenAI側の話で、こちらでは未検証。
- 事例は「人によってかなり違う」という調査結果なので、正解の分担ではなく**自分の作業で試して決める**材料として読む。

## このプロジェクトへの転用
- このリポジトリはすでに **`CLAUDE.md` が `@AGENTS.md` の1行**という推奨形になっている（`AGENTS.md`にはNext.js向けの注意書き）。追加の一本化作業は不要。
- これまでの「Codexに第二意見を聞く」（`knowledge/progress/day1-second-opinion-request.md`）は、事例①②④の「Claude Codeが作り、Codexが見直す／相談する」型に当たる。**Codexには書き換えさせず意見だけもらう**運用が、事例④と一致。
- 使い分けを決めるなら、「作る（Claude Code）」「見直す・行き詰まったときの相談（Codex）」「調べ直しはAIチャット」の3分担が、記事の事例と自分の運用の両方に合う。
